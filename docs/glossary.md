# Glossary

These are terms and their meaning in the context of this app.

| Term                      | Description                                                                                                                                                                                        |
| ------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| User                      | An entity that owns an account, most likely a human. Each user is only allowed to have 1 account.                                                                                                  |
| Account                   | All the data that identifies and is tied to a user in the system. Users are referenced by their account id.                                                                                        |
| Player                    | A player is an instance of an account in a game. An account can participate in multiple games, and so can have multiple players. However, an account can only be a single player in the same game. |
| Home Planet               | The Planet assigned to a Player when a game starts.                                                                                                                                                |
| Game                      | A match with one identity throughout creation, its lobby, active play, and completion.                                                                                                             |
| Game Listing              | A public overview of a game, including its status, player count, and the requesting account's membership.                                                                                          |
| Game Details              | Public game information, including configuration, players, lifecycle information, and the requesting player's available operations.                                                                |
| Game Configuration        | The settings chosen when creating a game, including its name, seats, turn interval, ruleset, and optional map seed.                                                                                |
| Lobby                     | The pre-start phase of a game, during which players can join or leave before the creator starts it.                                                                                                |
| Gameplay                  | Player-specific game views and operations, including Action submission and Readiness.                                                                                                              |
| Use Case                  | An operation-specific backend application class that owns one business operation and its dependencies; a router calls it directly.                                                                 |
| Ruleset                   | The persisted rules used by one game, including its Action Definitions, Effect Definitions, and other game settings.                                                                               |
| Action Definition         | Declarative Ruleset content that describes an Action's presentation, Effect Definitions, source and input requirements, and target slots.                                                          |
| Action Pool               | The Ruleset's ordered list of Pooled Actions offered to each player every Turn.                                                                                                                    |
| Pooled Action             | A Ruleset Action Pool entry with a stable Action ID and a reference to an Action Definition.                                                                                                       |
| Available Action Instance | A currently usable instance of an Action Definition offered to a player for submission.                                                                                                            |
| Action                    | Player-facing shorthand for an Action Definition, Pooled Action, Available Action Instance, or Action Submission when the distinction is not important.                                            |
| Action Submission         | A player's proposed use of an Available Action Instance, including their selected source, inputs, and targets.                                                                                     |
| Target Slot               | An entry in an Action Definition's `targets` record: a target tag paired with a Target Definition describing the required target type and constraints.                                             |
| Target Tag                | The key of a Target Slot. An Effect Definition uses the tag to find the selected target id in an Action Submission.                                                                                |
| Target Role               | An Effect Definition's internal name for a target. Its target mapping connects the role to a Target Tag in the Action Definition.                                                                  |
| Effect Definition         | Configured data in a Ruleset Action Definition that defines an Effect to create during Turn Resolution.                                                                                            |
| Effect                    | A concrete attempt to apply game behavior created from an Effect Definition during Turn Resolution.                                                                                                |
| Effect Outcome            | The recorded result of resolving an Effect: either `Resolved` when applied or `Prevented` as an expected game result.                                                                              |
| Resolved Action           | An Action Submission and its Effect Outcomes after the Turn has been resolved.                                                                                                                     |
| Turn                      | The period during which players decide which Actions to submit.                                                                                                                                    |
| Ready                     | The internal and gameplay term for a player whose Readiness is set. The UI presents this state as Locked in.                                                                                       |
| Readiness                 | A public, reversible player state that locks a player's Actions. When all players are Ready, the Turn ends early.                                                                                  |
| Lock in                   | The top-bar UI action that sets Readiness and makes the player Ready. The resulting Ready state is shown as Locked in; Cancel clears Readiness while the Turn is still collecting Actions.         |
| Turn Resolution           | The shared processing period after a Turn ends that computes the next game state.                                                                                                                  |
| Phase                     | An engine-owned, ordered stage of Turn Resolution that determines when a category of Effects resolves.                                                                                             |
| Tick                      | An internal precision sub-step within the Fleet Movement Phase used to sequence movement progress and arrivals.                                                                                    |

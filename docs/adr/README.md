# Architecture Decision Records (ADR) index

This index summarizes all accepted ADRs. When applying the concepts, you should read the related ADR for more context.

| ADR                                               | Summary                                                                                                                                                                                               | Use when                                                                         |
| ------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| 001-the-case-against-iac                          | We deploy via Railway and they don't recommend IaC, so we don't do it.                                                                                                                                | You're looking for infra as code.                                                |
| 002-avoid-docker-for-dev                          | We don't provide Docker containers for source we own, we run them directly.                                                                                                                           | You want to write dockerfiles.                                                   |
| 005-reverse-proxy                                 | A reverse proxy serves the frontend and the backend on the same port, avoiding cors issues.                                                                                                           | You're adding services, having cors issues or changing vite's dev server config. |
| 006-abstracting-3rd-parties                       | Only dedicated service/repository boundaries may talk to third parties directly.                                                                                                                      | Interacting with 3rd party infra.                                                |
| 007-code-sharing                                  | The only allowed shared code between backend and frontend are the tRPC router types from `backend/src/api/types`.                                                                                     | You think you need to share code.                                                |
| 008-no-import-side-effects-and-arguments-based-di | No import side effects outside app entry points. Do not create stateful objects in the module global scope, pass dependencies as arguments.                                                           | You need access to stateful objects.                                             |
| 009-trpc-return-types                             | Always write return types, except for tRPC and Tanstack Router, since they are built to leverage inference.                                                                                           | You touch the TRPC/Tanstack setup.                                               |
| 010-router-controller-repository                  | Every backend vertical should contain a router-controller-repository with strict responsibilities.                                                                                                    | You add a new feature to the backend API.                                        |
| 011-tick-processing-in-worker-thread              | Tick processing should stay decoupled from the web server so it can be extracted later. The web server may depend on worker code; worker code should not depend on the web server.                    | You add a new feature to the backend. tick-processing                            |
| 012-spawning-workers-takes-lots-of-memory         | Spawning ephemereal workers frequently takes a lot of memory because node cannot optimize it.                                                                                                         | You need to spawn workers / processes.                                           |
| 013-use-results-and-never-throw                   | Never throw for expected errors. Return `Result` values to represent runtime errors. Wrap third-party calls that may throw with `Result.tryCatch`. Only fatal crash-the-process errors may be thrown. | You deal with expected, unexpected and 3rd party errors.                         |
| 014-pnpm-workspaces-and-shared-railway-monorepo   | We use a pnpm workspace, which offers nice DX and works well with Railway.                                                                                                                            | Adding project commands or new packages.                                         |
| 015-zod-validation-must-be-type-representable     | Use Zod for parsing, not validation. Do not use zod functions that cannot translate to TypeScript types. `.int()`, `.email()`, most `.refine()`, etc are forbidden.                                   | You write zod schemas.                                                           |
| 016-use-repositories-in-tests                     | Use repositories in tests, not the db directly. The db can only be used in repository tests since it is a direct dependency.                                                                          | Find yourself needing db level access in tests.                                  |
| 017-stubs-and-mocks                               | Use stubs when creating any data in tests. Create the stub if it doesn't exist in a file next to the type for discovery and reusability. Use mocks for third parties that are hard to control.        | You need to create test data or need to use an uncontrolled 3rd party in tests.  |
| 018-result-handling-in-tests                      | Assert the whole Result object in tests, not its individual properties. `expect(result).toEqual(Result.Success(expectedValue))`.                                                                      | You assert Results in tests.                                                     |
| 019-use-assert-for-runtime-invariants             | Do not leave expected invariants implicit, use explicit `Assert` calls.                                                                                                                               | Some invariants cannot be represented by the type system.                        |
| 020-tanstack-routes-for-routing-only              | Frontend Tanstack routes should only do the routing. The UI is implemented in `frontend/src/features/` in vertical slices.                                                                            | Adding new pages to the frontend.                                                |
| 021-snake-case-column-names                       | All Typescript schema column names should be `camelCased` but renamed to `snake_cased` for postgres via the `name` argument of column builders.                                                       | Updating database schemas.                                                       |
| 022-frontend-api-contract-types                   | Frontend code imports named backend contract types from `backend/src/api/types.ts`. It only defines types for frontend concerns and never duplicates, reconstructs, or deconstructs backend types.    | You need backend types in the frontend.                                          |
| 023-storybook-for-design-system-inspection        | Add Storybook stories for all components in `frontend/src/components`. This is used for manual inspection only for now.                                                                               | You're adding new components to the design system.                               |
| 024-playwright-for-frontend-end-to-end-tests      | Write frontend E2E tests using Playwright with role-based selectors, POMs, Clerk auth, etc.                                                                                                           | You're writing e2e tests.                                                        |
| 025-backend-initiated-db-migrations               | The backend migrates the database on boot.                                                                                                                                                            | You're changing the database schema.                                             |

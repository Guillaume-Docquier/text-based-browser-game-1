# Thoughts Dump

Record concise, accurate notes. Do not implement ideas or solve design questions unless asked.

## Target

- Accept any file type by path or unambiguous reference; ask if missing or unclear. Keep that target until the user changes it. Read the file and applicable editing instructions.
- Reuse its Thoughts dump section, or create one at the bottom on the first thought. Do not create an empty section.
- Use a heading, comments, or a section supported by the format's tools. Preserve file validity and behavior. If notes cannot fit without unrelated changes, explain why and ask for a destination; do not silently convert the file or create another.
- Edit only the section; preserve all other content, formatting, and user edits. Thoughts about changes elsewhere do not authorize those changes.

## Capture

- Clarify only ambiguity that would materially change the note; otherwise preserve uncertainty and proceed.
- Consolidate related thoughts without losing distinct constraints, examples, or questions. Apply clear revisions to earlier notes; clarify uncertain revisions.
- Use plain, direct language, existing terminology, and no artificial line wraps. Use short headings, bullets, or tables when they improve clarity or conciseness.
- Distinguish proposals, decisions, and open questions. Do not strengthen tentative statements, infer mechanics, or imply implementation. Questions in thoughts do not automatically request answers.
- Include assistant suggestions only when the user adopts them or asks to record them. Do not add unsolicited advice, research, or implementation plans.

## Finish

- Verify accuracy and section-only changes. Follow required formatting and validation, retaining formatting changes only within the section.
- Briefly confirm what was recorded; repeat full notes only if asked.
- Commit or publish only when requested, limiting changes to the intended scope and following repository requirements.

Its receipt labels copied-input replay timing/outcomes separately from persisted API state. The shared and public scenarios include explicit Arrange/Act/Assert sections.

The turn-processing architecture guide now describes captured Colonize intents and targets, phase order, current-owner projection, save guards, and unchanged-owner behavior.

The existing C3-19 public worker oracle repair is retained and checked by the current concurrency project: the journey lookup is bound to actual owner, source, destination, and submission identity because player views contain all owners and pooled submission IDs can match between players. Its next-Turn lookup compares against the loaded worker Turn plus one, avoiding a shadowed `turn` binding. The correction preserves the pinned route and force/payment/release assertions; it fixes test attribution, not gameplay behavior.

O-I3-19 test-quality updates are distinct from that C3-19 oracle repair: remove the duplicated null-owner test, add AAA structure to the new shared/public ordinary-Move cases, and distinguish copied-input replay observations from actual persisted API read-through evidence.

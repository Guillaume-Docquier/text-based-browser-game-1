### Combat, presence, ordering and smallest deterministic fix

Actual presence means positive stationary fleet at destination with movement/destination/distance absent. A journey whose recorded origin is that planet remains in transit and is neither defender nor attacker. Outgoing partial departures leave only the stationary remainder as a defender; full outgoing departures leave none. All same-turn incoming fleets and builds are present before first Assault, irrespective of arrival tick; priority changes order of attacks, not who can defend.

Process tick groups ascending (20 movement ticks; distinct coincident planets tick0; exact-speed arrival tick20). Within a tie, canonical-sort candidate keys `(playerId, actionId, departureTurn, initiatingJourneyId, definitionOrdinal)` using stable ordinal string comparison, then existing persisted tools-ts Rng.shuffle (descending Fisher-Yates); consume no tie draw for singleton. Group planets canonically if coordination groups by destination; preferably one global canonical tick queue so unrelated object order never selects draw assignment. Dead attackers remain in the established queue and complete Prevented without resampling the survivors. Document exact draws/ordering algorithm for replay; do not sort by transient numeric effect ID or DB row order.

Before each Assault snapshot A=actual attacker current strength and D=sum ALL stationary enemy strengths (different owners included). Attacker loss=min(A,D); total defender loss=min(D,A), simultaneously from snapshot. No rounds, first strike, cloak, conquest or ownership change. If D=0, successful Resolved no-op and unchanged A. Remove zeros immediately, carrying removed IDs. Subsequent attacks see survivors; missing/dead actual attacker is Prevented.

For whole defender losses L, compute exact quotient/remainder of `L * defenderStrength / D`, floor each quota, then assign remaining units by descending remainder and ascending FleetId ties. Use safe arithmetic (e.g. localized bigint for exact products/remainders, convert bounded whole losses back), not floating tolerances that can invert ties/lose units. Require supported combat strengths/aggregate sums to be finite safe nonnegative integers; reject corrupt loaded data before mutation. Preserve total L exactly and never negative. Do not round A/D by owner or pick only one enemy.

Smallest ordering fix: canonical-sort locked submissions by `(playerId,id)` BEFORE effect construction, preserving each definition's declared cost/effect order; canonicalize Build execution by `(playerId,id,definitionOrdinal)` rather than insertion/effect ID. Existing UUID-v5 build identity remains unchanged. Thus a fixed set of build/name draws occurs in the same order under equivalent submission/fleet/property/DB permutations before Combat RNG ties. Keep names and RNG mechanism; no isolated RNG framework or identity rewrite. Detect corrupt multiple same-owner stationary build candidates with Result rather than arbitrary Object.values.find. Preserve a valid stationed survivor's name/ID and reinforce it; a moving fleet from that origin is not a candidate. Verify departure/continuation/outcome ordering with repeated pooled ActionIds across owners too.
